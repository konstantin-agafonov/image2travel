# 10. Откуда поступают данные

[Оглавление](README.md) · Далее: [географические парсеры](11-parsing-geography.md)

## Стратегия

Не парсить «весь интернет». Редактор выбирает стартовые регионы, затем для каждого создаёт реестр конкретных официальных страниц, Wikidata ID и страниц Wikivoyage. Машина собирает географию и структурированные факты, редактор подтверждает практические ограничения и размечает впечатления.

Постоянный каталог наполняется импортом и одобренным seed. Краткоживущие ответы на конкретные даты (прогноз, маршрут) попадают в кэш. Фото пользователя **не источник для автоматической записи в каталог**.

## Матрица источников

| Данные | Основной источник и доступ | Извлекаемые поля | Назначение в БД | Режим |
|---|---|---|---|---|
| География, POI | [OSM](https://www.openstreetmap.org/copyright), региональные [PBF Geofabrik](https://download.geofabrik.de/) | name, coordinates, tourism/natural/amenity, access, website, opening_hours | entities, external_ids, pois, entity_tags, claims | Локальная массовая первичная загрузка |
| Небольшое обновление OSM | Настроенный [Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API) | Те же теги и версия объекта | staging → каталог | Ограниченные выборки; коммерческий/собственный endpoint по условиям провайдера |
| Идентичность места | [Wikidata EntityData / Action API](https://www.wikidata.org/wiki/Wikidata:Data_access) | QID, labels, aliases, P625, P17, P131, P31, P856, sitelinks, references | external_ids, география, алиасы, claims | Малые группы известных сущностей |
| Туристический контекст | [Wikivoyage](https://en.wikivoyage.org/) через [MediaWiki revisions](https://www.mediawiki.org/wiki/API:Revisions) | Listings, описания, hours, price, координаты, URL | Кандидаты POI, редакционные заметки, claims | Только выбранные страницы |
| Общая справка | Wikipedia через MediaWiki API | Названия, описание, географические свидетельства | claims, aliases | Дополнительная проверка, не свежие тарифы |
| Часы, цены, закрытия | Сайт оператора/парка/музея/перевозчика | Расписание, исключения, тариф, бронь, доступ | pois, price_estimates, access_rules, claims | API/JSON-LD/HTML только с разрешением; иначе ручной ввод |
| Въезд | Пограничные/консульские органы страны назначения, напр. [EU](https://europa.eu/youreurope/citizens/travel/entry-exit/index_en.htm) | Гражданство, цель, срок, документы, исключения | travel_restrictions и claims | Для выбранной географии, редакционное подтверждение |
| Безопасность | [МИД РФ](https://www.mid.ru/), [FCDO](https://www.gov.uk/foreign-travel-advice), [US State Department](https://travel.state.gov/content/travel/en/traveladvisories/traveladvisories.html), сайты парков | Issuer, регион риска, уровень, ограничения, дата | travel_restrictions, access_rules, claims | Страницы/RSS/API, если есть; не смешивать аудитории advisories |
| Историческая погода | [Open-Meteo Historical Weather](https://open-meteo.com/en/docs/historical-weather-api) | Суточные температуры и осадки, dataset | climate_months, derived claims | Один выбранный многолетний период |
| Прогноз | [Open-Meteo Forecast](https://open-meteo.com/en/docs) | Осадки, ветер, температура, sunrise/sunset | api_cache | Только на доступном горизонте модели |
| Наземные переезды | [OSRM route/table](https://project-osrm.org/docs/v5.24.0/api/) с подходящим профилем | distance, duration, geometry, data_version | api_cache, расчёты Itinerary | По выбранным POI; не полный граф в БД |
| Курсы валют | [ECB reference rates](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html), [ЦБ РФ XML](https://www.cbr.ru/scripts/XML_daily.asp) | Дата, валюта, номинал, значение | exchange_rates | Один основной провайдер на поддерживаемую пару |
| Людность, бюджет на день | Официальная статистика посещений/туризма + ручная выборка тарифов | Методика, период, диапазоны | destination_months, price_estimates, claims | Оценка с основаниями, не «извлечение эмоции» |
| Профили впечатлений | Редактор по проверенным местам и условиям | Эмоции, темп, визуальный профиль, ритуалы | experience_json, visual_json, entity_tags, claims | Только manual/editorial |

## Что НЕ делать источником MVP

- Booking, Airbnb, Google Maps, Tripadvisor, Instagram и другие закрытые/ограниченные сервисы не скрейпить без договорного API и разрешения.
- Ссылки на агрегаторы жилья допустимы как место ручной проверки, не доказательство наличия и не лицензия на массовый сбор.
- Amadeus/аналоги — опциональный договорной API; тарифы кэшировать по условиям договора, не подменять ими гарантированную бронь.
- Eventbrite/Ticketmaster, полные GTFS-feed и изображения Wikimedia Commons — следующие этапы. Для фото проверять лицензию **каждого файла**, а не общую лицензию сайта.
- Nominatim не использовать для извлечения всех POI; по умолчанию публичный endpoint не включать.

## Лицензии и доступ

1. OSM — ODbL: обязательна атрибуция, а распространение производной базы может требовать share-alike. Разделение по таблицам само по себе не снимает обязанности. Перед публикацией seed/пакета проверить модель распространения и предоставить предусмотренные лицензией материалы.
2. Структурированные Wikidata — CC0, происхождение всё равно сохраняется. Wikipedia/Wikivoyage — условия CC BY-SA для конкретного содержимого; сохранять revision и атрибуцию, не переносить чужие тексты в якобы собственный summary.
3. Open-Meteo — атрибуция данных; права доступа к бесплатному API и коммерческому тарифу проверять отдельно. Лицензия данных не гарантирует бесплатный коммерческий сервис.
4. Для официальных сайтов публичность страницы не равна разрешению на скрейпинг. Проверять ToS, robots, разрешённые объёмы и хранение; robots не является лицензией.
5. Лимиты считать по всему приложению, не по пользователю/процессу. Не обходить их переключением IP/провайдеров.

Политики OSM и Open-Meteo сверены при подготовке плана 2026-10-24; их следует перепроверить перед реализацией. Доступность ECB в этой среде не подтверждена (таймаут); адаптер требует отдельного smoke-теста и локальных fixtures, не предположения о доступности.

## Реестр провайдеров

Каждая запись конфигурации содержит provider ID, base URL, разрешённые hosts/paths, способ получения, лицензию, атрибуцию, concurrency, request/day и bytes/day, timeout, разрешение хранения, parser version и дату проверки условий. Для региона дополнительно — точные URL официальных страниц и соответствующие entity ID.

Провайдер включается только после проверки этих полей. Если права или доступ неизвестны, режим `manual_only`; импорт не обходит ограничение через браузер.
