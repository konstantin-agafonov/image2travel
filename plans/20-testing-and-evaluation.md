# 20. Тестирование и оценка качества

[Оглавление](README.md) · Далее: [этапы реализации](21-delivery-and-roadmap.md)

## База и импорт

- Создание пустой БД всеми миграциями, проверки foreign keys, CHECK, типов entities, схем JSON и current claims.
- Повторный seed/импорт не дублирует entities/external IDs/snapshots/claims и не меняет редакционные поля.
- Новая версия факта сохраняет историю, активирует один current, атомарно обновляет проекцию/FTS.
- Конфликт, старый seed поверх свежего факта, parser drift, partial batch и падение перед commit не оставляют противоречивую активную запись.
- Восстановление бэкапа WAL-safe способом, FTS insert/update/delete/rebuild, schema checksum.
- Отсутствие critical provenance, сломанная field_path-ссылка и цикл claim dependencies выявляются data-check.

## Парсеры и HTTP

Fixtures сохранённых разрешённых ответов, без сети в обычном CI. Parser — чистая функция. Покрыть:

- OSM node/way/relation, representative vs entrance, private/foot=no, неполную geometry, дубли ID.
- Wikidata ranks/qualifiers/references, somevalue/novalue, aliases, redirect/missing ID.
- Wikivoyage nested templates, языковые варианты, missing coordinates, неоднозначные hours/price.
- Official HTML/JSON-LD: смена selector, устаревшая разметка, детский/взрослый тариф, «от», налоги, последнее время входа, PH и сезон.
- Погода: units, null, несовпадение длин массивов, далёкие даты, grid cell, DST, неполные годы и сумма/среднее осадков.
- OSRM: неправильный профиль, NoRoute/null, большой snapping, асимметричная матрица, seconds/meters.
- FX: XML namespaces, nominal≠1, десятичная запятая, валюта без курса, выходной день.
- HTTP: timeout/429/Retry-After/304/403, body limits, provider error при 200, redirection SSRF и секреты в URL.

Live smoke-тесты только отдельно, по разрешённым минимальным запросам и с лимитами; не скрейпить публичные сервисы каждым CI-run.

## Подбор и маршрут

Фиксированная версия небольшого каталога для воспроизводимого результата. Проверить жёсткий fail против unknown, crowd неизвестен, exact не подтверждён, меньше трёх кандидатов, бюджет person/group/on_site, разные валюты и nights/days.

Маршруты: реальные transfer buffers, закрытый POI/сезон, полярный день/ночь, DST/полночь, неизвестный рейс, доступность, темп, невозможный бюджет, план B и источник у каждого критичного блока.

Property tests: никакая версия весов не возвращает запрещённое место; перенос начала активности не создаёт пересечение; total low ≤ total high; маршруты не используют retired POI.

## MCP и skill

Smoke через Inspector/SDK: tools list/call, схемы результатов, resources, ошибки, рестарт между подбором и маршрутом, stdout содержит только MCP, stderr не ломает протокол. Проверить актуальную закреплённую версию FastMCP минимум с тремя host.

Экспорты: round-trip parsing Markdown/ICS/GeoJSON, timezone/escaping/UID, lon/lat, TTL, path traversal/symlink, orphan после сбоя.

## Eval по фото

Не менее 30 разнообразных случаев со входами и ожидаемыми свойствами, включая:

1. Тихое озеро на рассвете.
2. Горный снег при неподходящих датах.
3. Похожее впечатление дешевле.
4. Неоднозначная геолокация.
5. Слишком маленький бюджет.
6. Пользователь без дат/паспорта.
7. Место с закрытой тропой.
8. Толпа за кадром/пик сезона.
9. Ограниченная мобильность.
10. Далёкие даты без прогноза.
11. Сломанный внешний API.
12. Противоречащие источники.

Для стабильных машинных eval использовать frozen snapshots/catalog, а не меняющиеся живые цены. Отдельно подготовить минимум 10 многошаговых MCP-вопросов с проверяемыми ответами по fixture-каталогу: подбор → детали → построение → валидация. Vision/качество прозы оцениваются рубрикой, не только exact string match.

## Метрики и gate беты

- 100 % критичных **уверенных** рекомендаций имеют проверяемое provenance; unknowns обозначены, а не замаскированы.
- Ни один подтверждённый blocker не проходит как valid.
- Каталог: 30–50 active направлений с 10–15 выбранными POI и проверенным доступом anchors; completeness по полям измеряется отдельно.
- Три концепции при достаточном наборе проходят diversity review и объясняются реальными компонентами.
- Маршруты 1–7 дней проходят автоматические проверки и редакционный review природных сценариев.
- Минимум три host проходят полный путь; локальный подбор имеет измеренный целевой p95 до 2 секунд без внешней сети, сетевые вызовы имеют bounded timeout/частичный результат.
- Пользовательские метрики беты: CSAT, доверие источникам, полезность компромиссов и готовность действовать. Сбор ручной/добровольный; автоматическая аналитика — следующий этап.
