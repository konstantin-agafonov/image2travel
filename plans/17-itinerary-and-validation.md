# 17. Построение и валидация маршрута

[Оглавление](README.md) · Далее: [ответ и экспорт](18-response-and-exports.md)

## Детерминированный скелет

`build_itinerary` не пишет прозу и не вызывает LLM. Он получает brief и destination ID, читает проверенные данные и возвращает структуру, которую объясняет host.

1. Выбрать базу и проверить диапазон дней.
2. Взять anchors, optional, backup и logistics из destination_pois.
3. Исключить закрытые/запрещённые/несовместимые POI по датам и условиям доступа.
4. Группировать точки географически; для критичных переездов использовать профильную матрицу/проверенные ручные времена.
5. Ставить 2–4 якорных впечатления в день; меньше в день прибытия/отъезда.
6. Выбирать время суток по best_time и цели опыта. Рассвет/закат — локальный астрономический расчёт с оговорками, не фиксированное «06:30» для любого месяца.
7. Учитывать hours, длительность, последний вход, бронирование, сезон и известные праздники.
8. Добавлять буферы на transfer, еду, очередь, отдых и check-in; effort соответствует brief.
9. Считать смету на группу/человека и дни/ночи отдельно, с резервом 10–15 %.
10. Добавлять план B для дождя/усталости: он тоже должен быть доступен по времени/сезону.

Если время рейса неизвестно, первый/последний день не получает плотного расписания. Перелёт/трансфер из аэропорта не считаются включёнными без данных.

## Блок Itinerary

Активность: POI ID, название, координата доступа и её тип, local start/end с timezone, длительность, effort, назначение опыта, цена/units, необходимость брони, sources/claim IDs, unknowns.

Transfer: origin/destination, mode/profile, duration, buffer, distance, метод (`routing_api` / `curated` / `estimated`), checked_at/data_version. Для маршрута нужны реальные входы; центр озера не навигационная цель.

Budget: category, количество, единица, low/high, валюта, original price IDs/claims, FX/date, включения/исключения и допущения. «Расходы на месте» не называть полной стоимостью поездки.

## Валидация

| Проверка | Invalid/blocker | Needs review/warning |
|---|---|---|
| Расписание | Перекрытия, подтверждённо закрытая точка, позднее прибытие после входа | Неполные часы/праздники/неизвестная бронь |
| Доступ | Запрет, закрытая тропа, несовместимое effort | Неизвестный вход/уклон/правила |
| Переезды | Проверенная невозможность уложиться во время, NoRoute без допустимой альтернативы | Грубая оценка, непроверенное расписание транспорта |
| Бюджет | Подтверждённая нижняя граница выше лимита | Unknown costs, возможный выход верхней границы |
| Сезон/погода | Действующее закрытие/опасные условия по применимым данным | Далёкая дата без прогноза, климат не гарантирует погоду |
| Provenance | Критичная уверенная рекомендация без оснований | Stale/estimated по некритичному пункту |
| Темп | Невыполнимое суммарное время суток | Слишком много anchors/малые буферы для slow |

Проверять даты/timezone/DST, переходы через полночь, buffer, суммарный effort, даты действия правил. Валидировать ссылки с entity/claim и не позволять host подставить произвольную «подтверждённую» цену в edited Itinerary.

Feasibility score — объяснимая вспомогательная метрика, не вероятность успешного путешествия. Любой blocker определяет invalid независимо от среднего score.

## Этичная «инструкция по впечатлению»

Время и легальная точка просмотра, подходящие погодные условия, длительность подхода, одежда/снаряжение, способы снизить людность, разрешённый ракурс и фотооборудование, правила парка, запасной сценарий.

Не гарантировать туман/тишину; не отправлять через частный участок, закрытый перевал, опасную тропу или на запрещённый запуск дрона. Советы по природе не подменяют актуальные предупреждения спасслужб и парков.
