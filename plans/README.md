# Image2Travel — составной план

Image2Travel превращает фотографию в выполнимую поездку, сохраняющую **впечатление**, а не только визуальное сходство. MVP: skill + локальный MCP-сервер на Python, SQLite и файлы на диске.

Это план реализации, не описание уже работающего приложения. Команды, схемы и расположение модулей ниже — проектируемые контракты. Базовые решения исходного `PLAN.md` сохранены; структура БД и загрузка данных уточнены.

## Общие договорённости

1. SQLite — единственная runtime-БД; PostgreSQL и векторная БД не нужны для 30–50 направлений.
2. Host видит фото и ведёт диалог; сервер не вызывает LLM и не сохраняет пользовательские поездки.
3. Массовое наполнение каталога выполняет отдельная CLI-команда импорта, не пользовательский MCP-tool.
4. Проверенные факты, редакционные интерпретации и расчётные оценки имеют разные статусы.
5. Критичные неизвестные значения не превращаются в «безопасно», «открыто» или «виза не нужна».
6. Версионируемые seed-данные лежат в `src/image2travel/data/seed/`; runtime-файлы — в настраиваемом `IMAGE2TRAVEL_DATA_DIR` (локально `./data/`).
7. Полные DDL-блоки из частей 07–09 образуют проект первой схемы. Реализация должна проверить его миграциями и тестами; дополнительные CHECK/триггеры, описанные текстом, также обязательны.
